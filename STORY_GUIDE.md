# Story authoring guide

This guide is for people who want to write a story, not change the engine. The
game is a local-first chat story: content is JSON and local media under
`src/story/`; no account, server, analytics, or remote asset host is required.

The format is implemented in `src/engine/story.ts`. The browser Story Studio and
`bun run check` use that same parser, so an author sees the same errors in both
places.

## 1. Start here

```bash
bun install
bun run dev
```

Open `http://localhost:8080/` to play and `http://localhost:8080/studio.html`
to edit, validate, and preview story files. The Studio can load a story folder,
edit a JSON or theme file, show a nested route outline, download the edited
file, and open a phone-width preview. The browser does not write files back to
the selected folder: download the file and replace its matching source path.

Before sharing a story, run:

```bash
bun run check       # TypeScript, story validation, and tests
bun run build       # production build plus offline precache manifest
bun run preview     # serve the production build
```

The PWA caches same-origin build files after the first successful load. Saves
and preferences remain in that browser's local storage. Players can also export
and import a local JSON backup from Settings.

## 2. Story folder layout

```text
src/story/
├── story.json                         # game title, language, UI copy overrides
├── theme.css                          # palette and font tokens
├── characters/
│   └── alex/
│       ├── alex.json                  # profile
│       ├── chapter1.json
│       └── chapter2.json
├── locations/                         # optional in-person scenes
│   └── teahouse.json
└── assets/
    ├── portraits/alex.svg
    ├── alex/chapter1/window.webp
    └── sounds/
        ├── sounds.json
        └── ambience/evening.wav
```

Folders and file names are IDs. Use letters, numbers, and dashes; do not use
spaces. A character folder must contain a matching profile (`alex/alex.json`).
Chapter files are named `chapter1.json`, `chapter2.json`, and so on. Location
IDs are filenames without `.json`.

The starter includes the reusable Tutorial and Mai's five-chapter romance
ministory. Keep the Tutorial. It unlocks Mai after the first choice. Use Mai as
a feature tour, or rewrite her profile, chapters, places, and art for your own
narrative. When replacing Mai, retarget or remove the Tutorial's `unlock` step.
The story deliberately covers every character-chat step and includes Teahouse
and Riverside Garden scenes for Places-only steps.

## 3. Game identity, language, and interface copy

`story.json` is optional. Its fields are:

```json
{
  "title": "Letters at Dusk",
  "description": "A quiet story told one message at a time.",
  "lang": "en-GB",
  "ui": {
    "nav.chats": "Messages",
    "action.howToPlay": "How this story works",
    "story.end.finale": "You have reached this character's ending."
  }
}
```

- `title` updates the document title, hidden page heading, Settings title, and
  the installed PWA name generated by the production build.
- `description` updates the game's page description and PWA description.
- `lang` is a language tag (for example `en`, `en-GB`, or `fr`) and updates
  `<html lang>` for the game and How to play page.
- `ui` overrides built-in interface strings. Story dialogue remains your own
  authored text. Unknown keys and blank values fail validation.

The supported UI keys are defined in `src/engine/i18n.ts`. Current groups are
`skip`; `nav.*`; `action.*`; `settings.*`; `speed.*`; `volume.*`; `chat.*`;
`quiz.*`; `gallery.*`; `profile.*`; `state.new`; `story.end.*`; and `about.*`.
Values may contain `{name}`, `{count}`, `{who}`, `{age}`, or `{date}` where that
key uses a value. For example:

```json
{
  "lang": "de",
  "ui": {
    "nav.chats": "Gespräche",
    "nav.places": "Orte",
    "chat.replyCount": "{count} Antworten verfügbar.",
    "chat.replyCount.one": "Eine Antwort verfügbar.",
    "about.title": "Spielanleitung"
  }
}
```

The current keys are:

your story files in the language named by `lang`.

## 4. Create a character and profile

Create `characters/alex/alex.json`:

```json
{
  "name": "Alex",
  "unlocked": true,
  "dev": false,
  "teaser": "A short preview shown in the Chats list.",
  "color": "#0ea5e9",
  "initial": "A",
  "avatar": "portraits/alex",
  "order": 2,
  "age": 22,
  "birthday": "2 April",
  "tagline": "A short line shown at the top of the profile.",
  "interests": ["film photography", "late-night walks"],
  "likes": ["honest answers"],
  "dislikes": ["being interrupted"]
}
```

| Field | Meaning |
| --- | --- |
| `name` | Required display name. |
| `unlocked` | Visible in Chats at a new game when `true`; otherwise hidden until a story step unlocks the character. Defaults to locked. |
| `dev` | Hidden from Chats, Characters, and Gallery unless Dev mode is enabled. |
| `teaser`, `order` | List preview and sort order (lower values appear first). |
| `color`, `initial` | Avatar fallback. Use a contrasting CSS color and one initial. |
| `avatar` | Optional portrait path relative to `assets/`, without extension. |
| `age`, `birthday`, `tagline` | Profile details. A profile needs both `age` and `tagline`; `birthday` is optional. |
| `interests`, `likes`, `dislikes` | Optional lists of profile facts. If you provide any profile field, include the required age and tagline too. |

Age, birthday, and each list entry stay hidden until a `reveal` step runs. The
tagline is always shown. Reveal list entries by exact text, including case and
punctuation.

## 5. Write a chapter

Create `characters/alex/chapter1.json`. A chapter file is a JSON array and must
begin with a matching chapter card:

```json
[
  { "type": "chapter", "number": 1, "text": "First contact", "time": "Friday Evening", "at": "18:12" },
  { "type": "them", "text": "Hey, is this still a good time?" },
  {
    "type": "choice",
    "options": [
      { "label": "Yes, what's up?", "then": [{ "type": "them", "text": "I wanted to ask you something." }] },
      { "label": "Give me a minute", "then": [{ "type": "them", "text": "No rush." }] }
    ]
  },
  { "type": "story-end" }
]
```

The chapter number must match its filename. Chapter files are played in
number order. A new chapter should normally finish with `chapter-end`,
`story-end`, or `continue-elsewhere`.

### Character-chat step reference

The `type` field chooses a step. All examples below are elements that can be
placed in the chapter array or a choice's `then` array.

#### Messages, scene cards, and pacing

```json
{ "type": "them", "text": "A message from the character.", "typing": 800, "pause": 500, "at": "18:13", "duration": 2 }
{ "type": "me", "text": "A scripted player message.", "pause": 300 }
{ "type": "chapter", "number": 1, "text": "First contact", "time": "Friday Evening", "at": "18:12" }
{ "type": "divider", "text": "Later that day", "at": "20:00" }
{ "type": "divider", "text": "A brief transition", "style": "fade" }
{ "type": "status", "text": "last seen recently" }
{ "type": "rename", "name": "Unknown contact", "initial": "U" }
{ "type": "wait", "time": 1500 }
```

- `them.text` and `me.text` are required. When omitted, typing and reply pauses
  are calculated from message length: typing is about 300 ms plus 14 ms per
  visible character (clamped to 350–3,200 ms); pause is about 180 ms plus 35 ms
  per word (clamped to 180–1,200 ms). The player's text-speed setting scales
  these defaults.
- `typing` and `pause` remain explicit millisecond overrides from 0 to 60,000.
  Use them when a character should hesitate or rewrite a line. `duration` is a
  separate explicit whole-minute gap after a message. `at` pins the story clock
  to a time such as `18:13`.
- `speaker` is allowed on `them` only inside a Place conversation.
- A `chapter` step requires `number`, `time`, and `at`; use empty strings for
  blank `text` or `time`. `at: ""` means do not reset the clock.
- A normal `divider` remains in the thread. `style: "fade"` is a temporary
  card. Both may use `at`.
- `status` changes a character thread's presence line; it has no effect in a
  Place scene.
- `rename` changes the list and thread name until that chat is restarted. The
  profile name in JSON remains the reset name.
- `wait.time` is positive milliseconds and is capped at 60,000.
- Choice replies and quiz answers also receive a length-based player pause.
  Photo timing follows its caption; a captionless photo uses the minimum beat.

The story clock is separate from the device clock. A chapter or Place chat's
`at` seeds it. Text advances the clock by its word count plus a small message
unit; a photo adds a larger unit plus caption words. Each 50 units advances one
minute. `duration` overrides the following gap. A pinned `at` resets the
accumulator.

Character (`them`) messages turn `http://` and `https://` URLs into links. A
short emoji-only character message is rendered larger; player bubbles show read
ticks. `{name}` is substituted in character messages and photo captions. It is
not automatically substituted in scripted player lines or a choice's `say`.

#### Choices, stats, and gates

```json
{
  "type": "choice",
  "options": [
    {
      "label": "Ask a thoughtful question",
      "say": "Tell me more about that.",
      "trust": 1,
      "then": [{ "type": "them", "text": "Sure." }]
    },
    { "label": "Change the subject", "then": [] }
  ]
}
```

Each option requires `label`; `say` changes the message the player sends and
defaults to the label. `then` is the steps that follow the selected reply.
Effects can be set directly on the option or with a `stats` step:

```json
{ "type": "stats", "trust": 1, "bond": -1 }
```

Supported stats are `trust`, `feelings`, `attraction`, and `bond`. Each character
starts at 2. Profile bars are drawn against 20; stat values themselves are
numeric and are not clamped.

An option's `needs` locks it until conditions are met. Add `hint` so the locked
reply explains itself:

```json
{
  "type": "choice",
  "options": [
    {
      "label": "Read the note",
      "needs": { "trust": 5, "hint": "Build trust first (5+ Trust)." },
      "then": [{ "type": "them", "text": "Here it is." }]
    },
    { "label": "Not now", "then": [] }
  ]
}
```

Stat thresholds combine with AND. A choice can also use a milestone, a
remembered value, or a cross-chat milestone with a timer:

```json
{ "type": "milestone", "id": "met-after-dark" }
```

```json
{
  "type": "choice",
  "options": [
    {
      "label": "Open the timed message",
      "needs": {
        "milestone": "met-after-dark",
        "inChat": "alex",
        "waitSeconds": 10,
        "hint": "It arrives ten seconds after the milestone."
      },
      "then": [{ "type": "them", "text": "Now you can read it." }]
    },
    { "label": "Continue", "then": [] }
  ]
}
```

`inChat` selects the character thread whose milestone to check; it is only valid
with `milestone`. `waitSeconds` is a positive whole number and also requires a
milestone. A remembered-value gate uses `key` with exactly one of `is` or `not`:

```json
{
  "label": "Choose the window seat",
  "needs": { "key": "seat", "is": "window", "hint": "This depends on your earlier plan." },
  "then": [{ "type": "them", "text": "I saved the seat." }]
}
```

For automatic stat branches, use `branch`. All `needs` thresholds must match;
when `any` is present, at least one group must match:

```json
{
  "type": "branch",
  "needs": { "trust": 5 },
  "any": [{ "feelings": 7 }, { "attraction": 7 }],
  "then": [{ "type": "them", "text": "That works." }],
  "otherwise": [{ "type": "them", "text": "Not yet." }]
}
```

Branches can test stats only. Use a choice's `needs` for milestones or memory.

#### Milestones, memory, and conditions

```json
{ "type": "milestone", "id": "first-meeting" }
{ "type": "remember", "key": "shared-plan", "value": "museum" }
{ "type": "remember", "key": "shared-plan", "value": "museum", "chat": "alex" }
```

A milestone records when a named event occurred. A remembered value is stored
in this thread unless `chat` names another character ID. `if` supports exactly
one condition:

```json
{ "type": "if", "key": "shared-plan", "is": "museum", "then": [{ "type": "them", "text": "Saturday, then?" }] }
{ "type": "if", "key": "shared-plan", "any": ["museum", "park"], "then": [{ "type": "them", "text": "We have a plan." }] }
{ "type": "if", "key": "shared-plan", "not": "museum", "then": [{ "type": "them", "text": "We chose somewhere else." }] }
{ "type": "if", "key": "shared-plan", "none": ["museum", "park"], "then": [{ "type": "them", "text": "We have not chosen yet." }] }
```

Missing values do not match `is` or `any`; they do match `not` or `none`.
Milestones and quiz results are also remembered internally as `_m:<id>` and
`_q:<id>`.

#### Unlocking chats and adding later messages

```json
{ "type": "unlock", "chat": "alex" }
{ "type": "add-to-chat", "chat": "alex", "steps": [{ "type": "them", "text": "A message appended from another thread." }] }
```

`unlock` makes a character visible in Chats. `add-to-chat` appends steps to that
character's queue; they play the next time the recipient thread runs. Steps
inside `add-to-chat` use the character-chat format, even when appended from a
Place.

#### Profile reveals and typed replies

```json
{ "type": "them", "text": "I'm 22." }
{ "type": "reveal", "fact": "age" }
{ "type": "reveal", "fact": "birthday" }
{ "type": "reveal", "fact": "interests", "value": "film photography" }
{ "type": "reveal", "fact": "likes", "value": "honest answers" }
{ "type": "reveal", "fact": "dislikes", "value": "being interrupted" }
```

Age and birthday do not take a `value`; list facts must exactly match a profile
entry. `ask` collects typed input. The special key `name` is shared across
threads and can be inserted into character messages and photo captions as
`{name}`. Other keys are local to that chat:

```json
{ "type": "ask", "key": "name", "placeholder": "What should I call you?" }
{ "type": "them", "text": "Good to meet you, {name}." }
{ "type": "ask", "key": "favorite-tea", "placeholder": "Which tea do you like?", "feelings": 1 }
```

An `ask` can apply stat effects when submitted. It is not available in a Place
conversation.

#### Quizzes

Quizzes ask about information already shared. Wrong answers are removed and a
hint appears; the player can keep trying until the right answer. `pass` runs
after every question is answered. The result is remembered under `_q:<id>` as
`clean` (all right on the first attempt) or `retry`:

```json
{
  "type": "quiz",
  "id": "first-quiz",
  "questions": [
    {
      "q": "Which day did we choose?",
      "hint": "Check the earlier messages.",
      "answers": [
        { "text": "Saturday", "right": true, "reply": "That's it." },
        { "text": "Monday", "reply": "Not that day." }
      ]
    }
  ],
  "pass": [{ "type": "them", "text": "You remembered." }]
}
```

Each question needs at least two answers and one `right: true`. Answers can
also have stat effects.

#### Photos, galleries, and optional content

```json
{ "type": "photo", "name": "alex/chapter1/cafe", "alt": "A table beside a rain-streaked window", "caption": "I saved you a seat." }
{ "type": "photo", "from": "me", "name": "alex/chapter1/postcard", "alt": "A postcard with a hand-drawn map", "gallery": "misc" }
{ "type": "photo", "name": "alex/chapter1/portrait", "nsfw_version": "alex/chapter1/portrait-alt", "alt": "Alex in a blue jacket" }
```

Supported image formats: SVG, PNG, JPG/JPEG, WebP, GIF, and AVIF. Use paths
relative to `assets/`, without extensions. `alt` is required. Photos go into
the sender's Gallery folder by default; `gallery` can be `misc` or another
character ID. A filename beginning with `misc_` also goes into General. Avatar
portraits appear in Gallery from the start.

The SFW version is shown by default. `nsfw_version` selects a second local image
when the player enables the optional content setting. Any step can instead be
marked `"nsfw": "yes"` and will be skipped in SFW mode. Do not put both options
on one photo. In this starter, the content switch is under Dev mode; disabling
Dev mode returns to SFW.

#### Sounds

```json
{ "type": "sound", "sound": "chime" }
```

Built-in voices are `synth`, `rise`, `fall`, `chime`, `ping`, `pop`, `thud`,
`sparkle`, `whoosh`, `type`, and `chat1`–`chat5`. A file under
`assets/sounds/` can be named with or without its `sounds/` prefix. Supported
formats are MP3, OGG, WAV, M4A, AAC, FLAC, and OPUS.

`assets/sounds/sounds.json` is optional and maps events, volumes, and an
ambient loop:

```json
{
  "enabled": true,
  "volume": 0.6,
  "ambient": { "default": "ambience/evening", "volume": 0.22 },
  "events": {
    "them": "chime",
    "me": "type",
    "choice": "ping",
    "quiz": "pop",
    "stat": "whoosh"
  }
}
```

The starter can generate a local WAV without extra packages:

```bash
bun run sound:make                 # short notification chime
bun run sound:make -- --ambient    # quiet, seamless loop for the Teahouse
```

Event names are `them`, `me`, `choice`, `quiz`, and `stat`. Set an event to
`null` to silence it. A Place can select another local ambient file with its
`ambient` field. The player has master, ambience, and effects volume sliders.
Sounds wait for a user gesture because browsers may block autoplay.

#### Ending markers

These markers write a clear status message to the thread:

```json
{ "type": "chapter-end" }
{ "type": "story-end" }
{ "type": "continue-elsewhere", "for": "the Teahouse scene" }
```

Use `chapter-end` for a pause in a continuing storyline, `story-end` for a
finished character arc, and `continue-elsewhere` when another chat or place
holds the next part. Put the chosen marker at the end of the route.

## 6. Places: in-person conversations

Create a file in `locations/`. A place requires `name` and `host`; the host must
be a character ID:

```json
{
  "name": "The Teahouse",
  "host": "alex",
  "icon": "🍵",
  "color": "#7d624a",
  "teaser": "A short description above its scenes.",
  "order": 1,
  "ambient": "ambience/evening",
  "dev": false,
  "chats": [
    {
      "id": "first-visit",
      "title": "Saturday · afternoon",
      "teaser": "A quick catch-up.",
      "at": "16:20",
      "unlocked": true,
      "chat": [
        { "type": "them", "text": "You made it.", "speaker": "Alex" },
        { "type": "me", "text": "I said I would." },
        { "type": "choice", "options": [{ "label": "Save a seat", "then": [] }] }
      ]
    },
    {
      "id": "after-hours",
      "title": "After hours",
      "unlocked": false,
      "chat": [{ "type": "them", "text": "This scene is unlocked by a story step." }]
    }
  ]
}
```

Optional place fields: `icon`, `color`, `teaser`, `order`, `ambient`, and
`dev`. Each chat needs a unique `id` within its place and a `title`. `unlocked`
defaults to `true`; use `unlock-place` to reveal a locked scene:

```json
{ "type": "unlock-place", "place": "teahouse", "chat": "after-hours" }
```

`speaker` labels a person in the room; untagged `them` lines use the place host.
Places have their own story clock, transcript, milestones, remembered values,
and completion state. They do not show character profiles or stat bars. Supported
Place steps are `them`, `me`, `divider`, `sound`, `photo`, `wait`, `choice`,
`milestone`, `remember`, `if`, `unlock`, `unlock-place`, and `add-to-chat`.
`ask`, quizzes, stats, status changes, character profile reveals, and chapter
cards belong in character chats.

`theme.css` sets the Tailwind v4 tokens used by the interface. Keep these names
and choose new values for your story:

```css

  --font-sans: ui-sans-serif, system-ui, sans-serif;
  --color-chat-950: #0f172a;
  --color-chat-800: #1e293b;
  --color-chat-700: #334155;
  --color-out-600: #1d4ed8;
  --color-out-500: #60a5fa;
  --color-tick-400: #7dd3fc;
  --color-ink-100: #f1f5f9;
  --color-ink-300: #cbd5e1;
```

bundled into the build.

## 8. Player data and settings

The engine provides these screens without additional story steps:

- **Chats** lists unlocked characters, their teaser/last message, and a new
  marker until the thread has activity. Each thread resumes its saved queue.
- **Characters** shows unlocked profiles, revealed facts, and each contact's
  four stats. A profile fact stays a placeholder until its `reveal` runs.
- **Gallery** collects profile avatars and every photo reachable in story files,
  including unrevealed branch photos. Unseen photos appear as placeholders;
  revealed images open in a swipeable, keyboard-operable lightbox.
- **Places** lists unlocked in-person scenes. A completed scene stays visible as
  read; `unlock-place` can reveal a follow-up.
- **How to play** explains the player-facing chat controls. Its copy is part of
  the UI translation dictionary.

Settings supplies text speed, sound levels, six manual save slots, portable
backup/restore, a local-data explanation, a two-step delete action, and
developer controls. The five text speeds scale both calculated delays and
explicit story delays: Slow is 25% slower than Normal; Normal is twice the
unscaled delay; Quick reader uses the unscaled delay; Speedy is about 1.5× faster
than the unscaled pace; Skip through is the fast replay pace. Master, ambient,
and effects sliders multiply the levels in
`sounds.json`. Dev mode reveals `dev: true` characters/places and the stat
preview; the optional content switch is behind Dev mode and resets to SFW when
Dev mode is disabled.

- Chat transcripts, active queues, stats, memories, profile reveals, place
  scenes, photo unlocks, player name, and six manual save slots stay in browser
  storage on the device.
- Text speed, sound levels, Dev mode, stat previews, and content mode are
  preferences, separate from save slots.
- Restarting a chat confirms before clearing that chat's transcript, state, and
  stats. **Delete all chats** clears all game progress after a second tap.
- Settings can export and import a versioned JSON backup. Import validates the
  file and asks before replacing the game's data. Keep a backup before clearing
  browser site data or moving devices.
- There is no server sync. Clearing browser storage without a backup loses the
  local saves.

## 9. Validate and test a story

The validator checks JSON shape, required fields, IDs, images, sounds, profile
reveals, place hosts, sound settings, gate combinations, and references to
milestones and remembered values. Warnings call out missing hints, unused
conditions, large art, and conversations that may need review. Conversation
balance is an indicative route, not a universal writing target.

Use this loop:

1. Edit JSON/assets in your editor or Story Studio.
2. Run `bun run check` and fix errors first.
3. Open the game at 375px wide and play every choice route that matters.
4. Check keyboard navigation, screen-reader labels, gallery controls, and
   browser console output.
5. Run `bun run build` and test the production build with `bun run preview`.

### Mai test route

Mai's five chapters are a ready-made romance and engine tour. Complete the
Tutorial's first choice to unlock her. To exercise the less common paths, play
the first option in Chapter 1, then restart Mai's chat and play the second. In

## 10. Complete step checklist

| JSON `type` | Purpose |
| --- | --- |
| `chapter` | Chapter heading and story clock seed. |
| `them`, `me` | Character or scripted player message. |
| `divider` | Persistent divider or temporary fade card. |
| `status` | Character online/presence text. |
| `rename` | Temporary display name and initial. |
| `wait` | Typing pause with no message. |
| `choice` | Player replies, optional stats and gates, nested steps. |
| `stats` | Apply one or more stat changes. |
| `milestone` | Record a time-stamped event. |
| `remember` | Store a string value in this thread or a named character thread. |
| `if` | Branch on a remembered value. |
| `branch` | Automatically branch on stats. |
| `reveal` | Reveal a profile fact. |
| `ask` | Collect typed input. |
| `quiz` | Ask about previously shared story facts. |
| `photo` | Send a local image and optionally add it to a Gallery folder. |
| `sound` | Play a built-in voice or local sound file. |
| `unlock` | Reveal a character chat. |
| `unlock-place` | Reveal a place conversation. |
| `add-to-chat` | Append steps to a character thread. |
| `chapter-end` | Mark a chapter pause. |
| `story-end` | Mark a complete character arc. |
| `continue-elsewhere` | Point to another chat or place for continuation. |

Any step can use `"nsfw": "yes"` to make the entire step optional-content
only. `photo` can instead use `nsfw_version` for an alternate image.

## 11. Troubleshooting

| Symptom | Check |
| --- | --- |
| Character does not appear | Profile filename must match its folder; check `unlocked` and `dev`. |
| Chapter is skipped or rejected | Check the filename, first `chapter` step, and matching number. |
| A reply never unlocks | Add a `hint`; check each stat, milestone, wait timer, and remembered key. The validator warns when a referenced milestone has no declaration. |
| Profile detail stays hidden | Add a matching `reveal`; list values must match profile text exactly. |
| Picture is missing | Use an extensionless path relative to `assets/`; check capitalization and the file format. |
| Sound is silent | Check `sounds.json`, volume sliders, the first-tap audio rule, and that the file is under `assets/sounds/`. |
| A place scene is missing | Check `locations/<id>.json`, host ID, chat `unlocked`, and any `unlock-place` reference. |
| Changes do not show in a preview | Download edited Studio files into the source folder, reload the dev server, and check validation. |
| Edited dialogue does not replay | Progress is local; restart that chat or delete its progress after making a backup. |
| Saves disappeared | Restore a JSON backup; browser site-data clearing removes local storage. |
